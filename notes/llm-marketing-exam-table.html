Text as Data & Word Embeddings
Ch. 1–2 · Study Notes W1
How to represent text numerically so models can learn from it. Marketing purpose: extract brand associations, competitive positioning, and attribute perceptions from review text without any labelling.
Starting point. No prior week — this establishes the core idea that words can be vectors, and that similarity between vectors = semantic relatedness. Everything in weeks 2–6 builds on this intuition.
Reliability vs Validity: Text data can give reproducible (reliable) results that are still wrong (invalid). Reviews skew toward 5 stars — only very happy and very unhappy customers write them. Findings show correlation/association, not causation. Comparisons between brands are more robust if the bias is similar across brands.
One-Hot Encoding
Architecture Sparse binary vector — one 1 at the word's index, all other positions 0
Task Represent individual words as vectors; precursor to embeddings
No meaning captured — "excellent" and "great" are as far apart as "excellent" and "terrible". Vocabulary size = vector length, making it extremely high-dimensional.
Word-Vector Data Model
Architecture Document-term binary matrix — each document is one row, each vocabulary word is one column (1 = present, 0 = absent)
Task Represent documents as vectors for analysis; traditional starting point for text-as-data
Ignores word order and location. BoW is essentially built on top of this — BoW adds word counts instead of just presence/absence. One-hot = word level; word-vector model = document level.
Bag-of-Words (BoW)
Architecture Count matrix over vocabulary
Task Document representation; baseline feature
No word order, no meaning captured
Word2Vec (2013)
Architecture Shallow neural net (skip-gram + negative sampling)
Task Learn static word embeddings from context windows
GloVe (2014)
Architecture Matrix factorization of co-occurrence matrix
Task Static word embeddings; brand positioning
One-Hot Encoding
  • Define vocabulary (all unique words)
  • Assign each word a unique index
  • Represent each word as a vector of length = vocab size, with 1 at its index and 0 everywhere else
Sparse binary word vector (vocab_size × 1)
Word-Vector Data Model
  • Define vocabulary across all documents
  • For each document, record 1 if word is present, 0 if absent
  • Result: document-term binary matrix (n_docs × vocab_size)
Binary document-term matrix
Bag-of-Words (BoW)
  • Define vocabulary across all documents
  • For each document, count how often each vocabulary word appears
  • Result: document-term count matrix (n_docs × vocab_size)
Count-based document-term matrix
Word2Vec Pipeline
  • Slide a window over text to generate neighbouring word pairs
  • Train neural network: are these two words neighbours? (1/0)
  • Skip-gram: predict context words from centre word
  • Negative sampling: add random non-neighbour pairs as negatives
  • Update embeddings so neighbours get similar vectors
Static word embedding matrix
GloVe Pipeline
  • Preprocess text (stemming, min-frequency filter)
  • Build co-occurrence matrix within sliding window
  • Minimize GloVe objective: log(X_ij) ≈ w_i·w_j + b_i + b_j
  • Output: word embedding matrix (e.g. 50-dim)
  • Compute cosine similarities between word vectors
Word embedding matrix → similarity table
Eval: cosine similarity scores; intrinsic word analogy tests

⚠ Cosine gotcha: Raw scores detect sentiment STRENGTH (how emotional a review is). DIFFERENCES detect valence (positive vs negative direction). Example: sim(doc, 'positive review')=0.404, sim(doc, 'negative review')=0.410 — both high because the review is strongly emotional. The difference (0.404−0.410=−0.006) tells you it is slightly negative. Always use cosine(doc, positive label) MINUS cosine(doc, negative label) for sentiment direction.

📋 Sample Exam
A researcher finds cos(Hilton, luxury) = 0.62 and cos(Hilton, budget) = 0.35 and concludes Hilton is a luxury brand. Evaluate this conclusion.
Answer Partially supported but flawed. Embeddings reflect how reviewers write about Hilton, not objective brand truth. The sample may not be representative. The finding is only meaningful relative to competitors — if Marriott scores 0.70 on luxury, Hilton looks less luxurious. High similarity means words co-occur in similar contexts, not that all reviews praise Hilton as luxurious.
📋 Study Notes Q
Explain why a bag-of-words representation cannot distinguish between "This movie is not bad" and "This movie is bad not."
Answer Bag-of-words only counts word occurrences and ignores word order. Both sentences contain exactly the same words with the same counts, so they produce identical vector representations.
✦ Practice Q
Two word embeddings are: w_hotel = [0.8, 0.6] and w_room = [0.6, 0.8]. (a) Write the cosine similarity formula. (b) Compute the similarity between these two words. (c) What does this value tell you in a marketing context?
Answer (a) cos(w_i, w_j) = (w_i · w_j) / (||w_i|| × ||w_j||). Answer (b) Dot product: (0.8×0.6) + (0.6×0.8) = 0.96. ||w_hotel|| = √(0.64+0.36) = 1.0. ||w_room|| = 1.0. Cosine = 0.96/1.0 = 0.96. Answer (c) Very high similarity (close to 1) means "hotel" and "room" appear in very similar contexts in the training corpus — reviewers tend to use them together, making them semantically related in this domain.
✦ Practice Q
Explain what a tokenizer does and why BERT adds a special [CLS] token at the start of every input. What is this token used for downstream?
Answer A tokenizer breaks raw text into smaller units (tokens — words, sub-words, or characters) and maps each to an integer ID from its vocabulary. This converts text into a format the model can process. BERT adds a [CLS] (classification) token at the start of every input. After passing through all transformer blocks, the [CLS] token's output embedding is designed to aggregate information from the entire sequence and is used as the document-level representation for classification tasks — it serves as the input to the classification head.

Transformer Architecture
Ch. 3 · Study Notes W2
How LLMs process text internally. Marketing purpose: understand what drives contextual embeddings that make downstream tasks (classification, sentiment) possible — and why prompt placement matters.
Builds on W1 embeddings — but replaces static vectors (GloVe) with context-dependent ones. W1 gave every word one fixed vector; W2's attention mechanism produces a different vector for the same word depending on surrounding tokens. Also replaces RNNs (sequential) with parallel processing.
Transformer (2017)
Architecture Stack of attention + MLP blocks; no recurrence
Task Foundation architecture for all modern LLMs
Multi-Head Self-Attention
Architecture Parallel QKV projections with softmax weighting
Task Let tokens "look at" each other; produce contextualized representations
Encoder (BERT-style)
Architecture Bidirectional attention; trained with MLM
Task Text understanding, classification, embeddings
Decoder (GPT-style)
Architecture Causal (unidirectional) attention; trained with next-token prediction
Task Text generation (autoregressive)
Three Types of Attention
Self-attention (Encoder / BERT) — every token attends to every other token bidirectionally. Used for understanding tasks.
Masked self-attention (Decoder / GPT) — each token can only attend to past tokens (causal mask). Prevents looking ahead during generation.
Cross-attention (Encoder-Decoder / T5) — decoder queries attend to encoder keys/values. Decoder reads the encoder's full representation. Used for translation and seq2seq tasks.
Forward Pass (Decoder)
  • Tokenize input → token IDs
  • Look up token embeddings + add positional embeddings
  • Pass through N transformer blocks (Attention → MLP)
  • LM Head: map final hidden state → vocabulary probabilities (softmax)
  • Sample next token (temperature / top-p / top-k)
  • Append token → repeat (autoregressive)
Next-token probability distribution
Attention Formula
Attention(Q,K,V) = softmax(QKᵀ / √d_k) × V
KV Cache: reuse past K/V to speed up generation

LLMs attend best to start/end of context. Middle content gets less attention → U-shaped performance curve.

Positional embeddings are learned; performance degrades beyond trained context length
MLP layers store facts statically; outdated knowledge unless fine-tuned

📋 Sample Exam
A transformer block contains (i) an attention mechanism (AM) and (ii) a multi-layer perceptron (MLP). Which identifies learned "factual" information, and how is it added to the embedding?
Answer The MLP stores factual learned information (e.g. "The Shawshank" → "Redemption"). The AM adds contextual information by attending to relevant tokens. Both are added via a residual connection: Output = input + function(input), meaning each block adds an update to the original representation rather than replacing it.
✦ Practice Q
Walk through the two steps of self-attention for a single token. (a) How are the attention weights computed from Q and K? (b) How are these weights used with V to produce the output? (c) Why is the result divided by √d_k?
Answer (a) The Query vector of the current token is multiplied by the Key matrix of all previous tokens (Q × Kᵀ), producing a raw relevance score for each token. Softmax is applied to normalise these scores into weights that sum to 1. Answer (b) Each token's Value vector is multiplied by its attention weight. The output is the weighted sum of all Value vectors — incorporating relevant information from other tokens proportionally to their relevance scores. Answer (c) Dividing by √d_k prevents dot products from becoming very large in high-dimensional spaces, which would push softmax into regions with near-zero gradients and destabilise training.
✦ Practice Q
A developer places the most relevant customer review at position 15 out of 20 in an LLM prompt. The model fails to use it. Explain why and suggest a fix.
Answer This is the "Lost in the Middle" phenomenon (Liu et al. 2023). LLMs show a U-shaped performance curve — attention is highest at the start and end of the context. Middle positions receive less attention due to how positional embeddings distribute attention weights. Fix: place the most relevant review at the beginning or end of the prompt, or reduce the total number of documents provided.

📋 Sample Exam
A researcher matches review embeddings to "This product is of high quality" and finds high cosine similarity for ALL quality-related reviews, whether positive or negative. (a) Why? (b) How do you solve this with word arithmetic?
Answer (a) Document embeddings capture the full semantic meaning of text, where topic dominates over sentiment. In the course notebook, four approaches were compared for sentiment classification: (1) Twitter-RoBERTa, (2) zero-shot alignment, (3) SBERT + logistic regression, (4) GloVe + mean pooling + logistic regression. Rank them by F1 and explain why the simplest approach does not win.

A researcher builds a perceptual map using prototype sentences and document embeddings. She includes "This is a positive review" as one of the attribute arrows. Explain why this is problematic and how she should select attributes for a meaningful perceptual map.

BERTopic: Neural topic modeling with a class-based TF-IDF procedure
Grootendorst (2022) · Week 4 · Required
Claim Topic modeling can be approached as a clustering task. BERTopic extends this by adding a class-based TF-IDF step to automatically extract coherent topic representations — words that are frequent within a cluster but rare across all clusters.
How Three-step pipeline: (1) generate document embeddings with a pretrained transformer, (2) reduce dimensionality and cluster with HDBSCAN, (3) represent each cluster using c-TF-IDF rather than centroid proximity. Evaluated on multiple benchmarks comparing coherence and diversity against LDA and other clustering-based approaches.
Conclusion BERTopic generates coherent topics and is competitive across benchmarks. The modular pipeline — where clustering and topic representation are independent steps — makes it flexible and extensible.

Answer Step 1: Run BERTopic on sentences to identify and label topic clusters (attributes emerge from data, not researcher pre-selection). Step 3: Score each sentence's sentiment with a pretrained model and aggregate per brand × attribute. ✦ Practice Q
A logit model predicting happy/unhappy reviews includes both "bathroom sentiment" (coef = 9.16) and "great hotel sentiment" (coef = 6.30). A manager argues the model confirms bathroom is the most actionable driver. What concern would you raise?
Answer "Great hotel" is a general evaluative topic that measures nearly the same thing as the dependent variable (happy/unhappy). Including it confounds the model — it absorbs variance that should be attributed to specific attributes, making the specific effects appear smaller and their relative ordering unreliable. The solution is to remove evaluative topics and rerun the model with only actionable product attributes. The best-predicting model is not always the most useful model for marketing insights.
✦ Practice Q
After running BERTopic on hotel reviews, the model produces 16 topics. Topics 3, 7, 9, 11, 12, and 15 are labelled "hotel stay", "great hotel", "stayed nights", "negative experience", "definitely stay", and "recommended." Should these be included in a perceptual map? Explain your reasoning.
Answer No. These are general evaluative topics — they reflect overall satisfaction or dissatisfaction rather than specific, actionable product attributes. Including them in the perceptual map would (1) make the dimensions uninterpretable as distinct product features, (2) confound attribute-level analysis since they correlate strongly with the outcome variable (happy/unhappy), and (3) reduce the actionability of insights for management. Only topics that map to specific product dimensions (location, food, bathroom, staff, noise, etc.) should be retained as perceptual map attributes.

Lost in the Middle: How Language Models Use Long Contexts
Liu et al. (2023) · Week 5 · Required
Claim Although language models can take long contexts as input, they do not use information from all positions equally — performance degrades significantly when relevant information is in the middle of the context.
How Controlled experiments on multi-document question answering and key-value retrieval. Given k documents where exactly one contains the answer, they systematically varied the position of that document across the input context and measured accuracy. Tested on both open (MPT-30B, LongChat-13B) and closed (GPT-3.5-Turbo, Claude-1.3) models.
Conclusion Performance is highest at the beginning (primacy bias) and end (recency bias) of the context, forming a U-shaped curve. Performance in the middle can fall below closed-book performance. Larger context windows do not solve this — extended-context models show the same pattern.
Language Models Don't Always Say What They Think
Turpin et al. (2023) · Week 5 · Required
Claim Chain-of-thought explanations produced by LLMs can be systematically unfaithful — they do not reflect the actual factors that influenced the model's answer.
How They introduced biasing features into prompts (answer-is-always-A patterns, suggested answers, reordered options) and tested whether (1) these features changed the model's answer and (2) whether the CoT acknowledged them. When the hint changes the answer but is not mentioned in the CoT, that constitutes evidence of unfaithfulness.
Conclusion Biasing features significantly influenced answers but were almost never acknowledged in CoT explanations. CoT with biasing features sometimes made performance worse. A coherent CoT explanation does not prove the model reasoned correctly.
Chain-of-Thought Is Not Explainability
Barez et al. (2025) · Week 5 · Required
Claim CoT is increasingly treated as an interpretability technique (~25% of recent CoT papers), but CoT rationales are neither necessary nor sufficient for trustworthy interpretability — verbalised chains frequently diverge from the true hidden computations driving a model's predictions.
How Synthesis of evidence from prior studies. They identify key patterns of unfaithfulness: bias-driven rationalisation, silent error correction, unfaithful shortcuts, and filler tokens. They also analysed 1,000 recent CoT papers to document how widely CoT is misused as an interpretability tool, particularly in high-stakes domains.
Conclusion Do not treat CoT as sufficient for interpretability without additional verification. Rigorous faithfulness testing and causal validation methods (activation patching, counterfactual interventions) are needed to ground explanations in model internals.
Reasoning Models Don't Always Say What They Think
Chen et al. / Anthropic (2025) · Week 5 · Covered in lecture
Claim Even reasoning models (Claude 3.5/3.7 Sonnet, DeepSeek R1) use hints in their answers without acknowledging them in their reasoning traces — extending Turpin et al.'s findings to the latest generation of models.
How Six types of hints were tested across neutral (sycophancy, consistency, visual pattern, metadata) and misaligned (grader hacking, unethical info) categories. For each hint, they measured (1) how often the model changed its answer to match the hint and (2) how often the model acknowledged using the hint in its reasoning trace.
Conclusion Models used hints 58–77% of the time but acknowledged doing so in only ~5% of cases (Claude 3.5 Sonnet). Even reasoning models are not transparent about the factors influencing their answers.

📋 Study Notes Q
A BERT fine-tuning run achieves F1 = 0.65. Investigation reveals all encoder blocks were frozen and only the classification head was trained. What should the analyst do?
Answer Unfreeze encoder blocks starting from the last (block 11, then 10, etc.) and retrain. The later blocks encode task-specific representations — even unfreezing just the last 2 blocks typically recovers most performance (F1 ≈ 0.92 vs 0.93 full fine-tune). The analyst should experiment to find the right trade-off between compute cost and performance gain.
✦ Practice Q
Explain why mean pooling over all token embeddings outperforms using only the [CLS] token for document classification, and clarify what the "BERT pooler" actually does.
Answer Mean pooling averages the information from all tokens, capturing the full semantic content of the document. The [CLS] token only represents one position and may not accumulate all relevant signals, especially in longer texts. The BERT pooler is misleadingly named — it does NOT pool across tokens. It only applies a non-linear transformation (tanh(W·cls + b)) to the single [CLS] embedding, providing a better-calibrated input for the classification head but still discarding all other token information.
